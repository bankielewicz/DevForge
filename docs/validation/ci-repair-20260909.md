## Diagnosis and selected remedy

The failing runner was Ubuntu image `20260907.300.1`, with Bubblewrap `0.9.0-1ubuntu0.1`. Its failure was `bwrap: setting up uid map: Permission denied`. The old logs did not expose the AppArmor sysctl/profile state; the revised setup records the restriction and only applies the profile on the matching failure path.

Inspected Ubuntu package `apparmor-profiles` version `4.0.1really4.0.1-0ubuntu0.24.04.7`. It supplies `/usr/share/apparmor/extra-profiles/bwrap-userns-restrict` with ABI 4.0, allowing Bubblewrap's namespace setup and denying capabilities in its executed child profile. The workflow uses the installed Ubuntu package's file, not a downloaded custom profile. An already functioning runner keeps its policy. The final unchanged preflight remains mandatory after setup.

Sources: [Ubuntu namespace restriction guidance](https://discourse.ubuntu.com/t/understanding-apparmor-user-namespace-restriction/58007) and [AppArmor 4.0.1 profile](https://gitlab.com/apparmor/apparmor/-/raw/v4.0.1/profiles/apparmor/profiles/extras/bwrap-userns-restrict).

The existing real-isolation tests cover writable candidate versus protected authority and an empty namespace with hidden host files and owned PID scope. These deterministic tests do not establish nested native Codex/Claude sandbox compatibility.
